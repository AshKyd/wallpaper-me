# Palette Backgrounds

[PaletteBackground](../src/lib/components/PaletteBackground/PaletteBackground.svelte) draws generative SVG art from a colour palette. The shape of a palette is `Palette` in [paletteUtils.ts](../src/lib/components/PaletteBackground/paletteUtils.ts); the sample data is [palettes.json](../palettes.json).

## Library

- The SVG generation is also built as a library from [index.ts](../src/lib/index.ts) (`npm run build:lib`, using [tsconfig.lib.json](../tsconfig.lib.json)); see the [README](../README.md). `paletteSvg()` in [svg.ts](../src/lib/components/PaletteBackground/svg.ts) is the main entry. The app's `buildWallpaperSvg()` uses it too.
- Everything reachable from `index.ts` must use relative `.js` imports (no `#lib`, `$lib`, or Svelte), as `tsc` compiles it as it is.

## Usage

- Props: `palette`, `variant` (`'circles' | 'triangles' | 'diamonds' | 'bands' | 'flowers' | 'checkerboard' | 'hexagons' | 'bokeh' | 'mondrian' | 'stripes' | 'midcentury' | 'artdeco' | '80s' | 'emoji-storm' | 'neon'`), `seed`, `gap` (borders between shapes, 0 to 0.4 of shape size; only `hexagons` and `mondrian` use it), optional `children` layered above.
- `tone` recolours the art (`pastel`, `dark`, `subtleDark`). See "Tones".
- Depth props for `circles`, `flowers` and `bokeh`: `depthOfField`, `focalPoint`, `blurAmount`, `parallax`, `parallaxPoint`, `parallaxDistance`. See "Depth: blur and parallax".
- The component fills its parent. Give the parent a size.
- The artwork is drawn for the container's shape, so nothing important is cropped (a fixed 3:2 canvas cut off bands on wide, tall and phone screens).
  - [PaletteBackground.svelte](../src/lib/components/PaletteBackground/PaletteBackground.svelte) measures itself with `bind:clientWidth`/`bind:clientHeight` and calls `canvasSizeFor()` in [canvas.ts](../src/lib/components/PaletteBackground/canvas.ts).
  - Height is always 800 and width is `800 * ratio`. The ratio is clamped to 0.5-3 and rounded to 0.25 steps, so a wider screen shows more pattern at the same motif size, and a window drag only redraws when it crosses a step.
  - Within a step the SVG's `preserveAspectRatio="slice"` crops the small remainder (about 6% at most).
  - Before the first measurement (and on the server) the size is 1200x800, so there is no layout shift.
  - Generators receive `width` and `height` in `GeneratorInput` and must not use fixed canvas constants. `packCircles()` scales its attempts by area to keep density constant.
  - Packed variants (`circles`, `flowers`) re-pack when the step changes; `bands` keeps its shape because it is laid out against the height.
- Randomness comes from `createRandom(seed)` in [paletteUtils.ts](../src/lib/components/PaletteBackground/paletteUtils.ts), which wraps the `msrand` package (the Microsoft C `rand`, 15 bits per call).
  - It discards `WARM_UP_STEPS` (4) outputs first: the generator is a linear congruential one, so neighbouring seeds start with nearly equal values, and the first choices in each artwork would barely differ between seed 1, 2 and 3.
  - It divides by `MAX_INTEGER + 1`, not `MAX_INTEGER`, as `msrand`'s `randDecimal()` can return exactly 1 and break `floor(random() * n)`.
  - `hashSeed()` (a string to a number, used by the stories and the depth nudge) is separate and unchanged.
- The same palette, variant and seed always give the same art. Seed by something stable (e.g. `hashSeed(title)`) so a note keeps its look.

## Generators

All live in [generators.ts](../src/lib/components/PaletteBackground/generators.ts) and return inner SVG markup. `generatePaletteArt()` is the entry point.

- `normalisePalette()` merges repeated hexes and sorts by `prominence`. The top colour becomes the base fill, so palettes that favour one colour keep its character.
- `circles`: `packCircles()` places non-touching circles, largest first. Styles are solid, ring and target (concentric). Colours are picked with `pickWeighted()`.
- `triangles`: jittered grid split into facets. Colour comes from `sampleRamp()` (palette sorted dark to light) swept across the canvas at a random angle, plus noise.
- `diamonds`: exact harlequin lattice. Colour is a fixed rule over the two diagonals (random step pair, shuffled colour deck), not random per tile. Even rows and columns get an inset diamond. Tiles have no borders; a same-colour hairline stroke only hides anti-aliasing seams.
- `bands`: solid swirling bands, one per palette colour, in the style of early Mac OS X and Ubuntu wallpapers. No gradients, transparency or outlines.
  - `bandsArt()` in [bands.ts](../src/lib/components/PaletteBackground/bands.ts) draws each band with exactly one smooth cubic Bézier. A band is filled from its curve round to the end of the fan, and bands are painted in order, so each later band covers the rest of the earlier ones. The only visible edges are the curves themselves, with no straight cuts, which keeps the swoosh sleek.
  - The bands fan out from one pivot like the blades of a fan. Every curve is the same single-bend arc (`bandCurve()`) running outwards from the pivot, and curves differ only by rotation about it, in equal steps.
  - `bandCurve()` bows to one side only and never turns back into an S: both control points sit on the same side of the chord, so the curve has no inflection. An S looks mechanical; one bend looks organic. A test checks the control polygon turns the same way throughout.
  - The pivot sits just outside a random side of the canvas, at a random point along it. The fan covers the angles the canvas spans (from the corner angles, plus a margin), so its closing ray and arc are always off-screen. The first band's curve is off-screen too, so its colour is also the backdrop.
  - Each curve ends exactly on a circle of radius `reach` (30% past the farthest corner), so the closing `A` arc is exact.
  - Palettes with one colour draw only the background.
  - The colours run dark to light across the fan, or reversed, picked by seed.

- `flowers`: 60s flower-power wall in [flowers/](../src/lib/components/PaletteBackground/flowers/).
  - [flowersArt.ts](../src/lib/components/PaletteBackground/flowers/flowersArt.ts) `layoutFlowers()` places 2-3 big flowers first (`BIG_RADIUS`, 240-310), then progressively smaller ones (from `FIRST_FOLLOWER_RADIUS`, 180, down to 34). The big few give the layout its random feel; the falling sizes fill the space between them.
  - Size comes from the attempt number, not from what fits, so sizes fall smoothly. Attempts scale with canvas area, so density is the same at any size.
  - For each flower, 12 random spots are tried and the one with the most clearance wins, which spreads flowers evenly. A flower is skipped unless it keeps `GAP` (14) clear of every other, so none touch. Tests check this.
  - Dots fill what is left, using `packCircles()` with the flowers as obstacles.
  - `backgroundCircles()` draws large flat circles behind everything, so the background isn't one solid colour. Each is the ground colour pulled 14-32% towards another palette colour, so they stay calm.
  - [daisy.ts](../src/lib/components/PaletteBackground/flowers/daisy.ts) `flowerPowerMotif()` draws one flower at unit radius in a `FlowerStyle`: `daisy`, `scallop`, `bloom` (uses `flowerMotif()` in [flower.ts](../src/lib/components/PaletteBackground/flowers/flower.ts)) or `target`.
  - [colourRoles.ts](../src/lib/components/PaletteBackground/flowers/colourRoles.ts) `assignColourRoles()` gives every flower the same roles (ground, outline, echo, fills), which keeps the wall cohesive. `outline` is the colour with the most contrast against the ground.

- `checkerboard`: a plain checkerboard whose colours form patterns. Cells are always plain squares.
  - Each cell belongs to a layer, and a layer is a colour pair. The cell's parity `(row + column) % 2` picks light or dark within its pair, so it stays a checkerboard everywhere. Patterns only change which pair a cell uses.
  - [layers.ts](../src/lib/components/PaletteBackground/checkerboard/layers.ts) `buildColourPairs()` pairs similar colours, so the checks are a quiet tonal shift rather than a jump between hues (e.g. blue against orange).
    - Colours are taken in order of prominence. Each takes its nearest unused neighbour if it is within `MAX_PAIR_DISTANCE` (`colourDistance()`) and has at least `MIN_PAIR_CONTRAST` luminance gap. Otherwise it pairs with a tint or shade of itself (`tonalPartner()`).
    - Pair 0 is the background and always starts with the most prominent colour. Up to three of the other pairs are used for motifs. A palette that makes only one pair gets a tinted fallback pair.
  - [motifs.ts](../src/lib/components/PaletteBackground/checkerboard/motifs.ts) `MOTIFS`: pure functions of cell offset and radius, returning `undefined` (outside) or a tone (0 main pair, 1 accent pair). Lines: `x`, `plus`, `starburst`, `asterisk`, `bowtie`, `chevron`, `diagonalStripes`, `zigzag`. Rings and fills: `o`, `diamondRing`, `squareRing`, `target`, `solidDiamond`, `solidCircle`, `frame`. Small repeats: `dots`, `cornerSteps`, `heart`, `arrow`. To add one, add an entry to `MOTIFS`; the story and tests pick it up.
  - `OVERLAYS` cover the whole board: `ripple` (rings), `sweep` (slanted stripes) and `rampShift` (pairs step left to right).
  - [checkerboard.ts](../src/lib/components/PaletteBackground/checkerboard.ts) `buildCheckerGrid()` uses either an overlay (35% of seeds) or motifs, never both. Motifs sit on a square or half-drop lattice, with 1 to 3 motif types shared as one, alternating, or by row. Spacing is more than twice the radius, so motifs never touch.
  - `renderCheckerGrid()` draws one square per cell. Cell size is 56, 64 or 72 by seed. Column and row counts are odd and the grid is centred, so there is a centre cell and any crop is symmetrical.

- `hexagons`: a hexagonal grid in a repeating colour pattern where no two hexagons that share an edge have the same colour. [hexagons.ts](../src/lib/components/PaletteBackground/hexagons.ts) `buildHexGrid()` and `renderHexGrid()`.
  - Every hexagon is one solid palette colour. Nothing is blended or shaded, so there are no gradients, transparency or tones.
  - `cycleOf()` arranges the palette colours in a loop where each is followed by a similar one: the shortest round trip through them (every order is tried, up to 8 colours), starting at the most prominent colour. Palettes are topped up to 5 colours (`MIN_CYCLE_COLOURS`) by blending the two colours furthest apart; a one-colour palette gains a tint first.
  - A hexagon at `(q, r)` takes loop position `(across * q + down * r + offset) mod length`. The pattern therefore repeats exactly every few hexagons, in diagonal runs of gradually changing colour, and every colour appears evenly across the whole canvas. This replaced a position-based gradient, which left prominent colours stuck in one corner and was not repetitive enough to read as a pattern.
  - A hexagon's six neighbours differ in loop position by `across`, `down` or `across - down`. `stepPairs()` only allows pairs where none is zero (so no edge matches), and among those keeps the pairs with the smallest total distance round the loop, so neighbours are as similar as possible. The seed picks between equally good pairs, the loop direction and the offset.
  - Hexagons are pointy-topped with a corner-to-centre size of 44, 56 or 68 by seed. The grid is centred on the canvas and runs past the edges.
  - `gap` shrinks each hexagon by that share of its size (capped at `MAX_GAP`, 0.4), so the backdrop shows through as a border. The backdrop is then the darkest palette colour, deepened a little. With no gap, a same-colour hairline stroke hides seams instead.
  - Tests: [hexagons/hexagons.test.ts](../src/lib/components/PaletteBackground/hexagons/hexagons.test.ts) check that edges never match, the pattern repeats, colours spread evenly, and neighbours are more alike than random colours.

- `bokeh`: soft out-of-focus lights over a dark gradient. [bokeh.ts](../src/lib/components/PaletteBackground/bokeh.ts) `bokehArt()`.
  - `splitBokehColours()` sorts the palette by `luminance()`. The darkest two colours (one if the palette has fewer than four) become the background `linearGradient`; the rest become the lights. A one-colour palette uses tints of its colour for the lights.
  - Each light colour gets one shared top-to-bottom `linearGradient` fill (faint tint to full colour) and one `linearGradient` stroke (a lightened version of the colour fading into the next). Discs pick a colour and get their own `opacity` (0.35-0.85), so overlaps blend.
  - Each disc has a Gaussian blur from one of four shared `filter`s (`BLUR_LEVELS`, 2-11 canvas units), chosen by size: larger discs are softer.
  - Parallax depth is flipped for `bokeh`: large, soft discs are the furthest and move least; small, sharper discs are nearest and move most. `bokehArt()` passes `smallest + largest - radius` as the `DepthItem.size`. Nearer discs are also drawn on top. One filter per disc, not per layer, so each layer's raster is static and parallax only moves it.
  - Discs may overlap (no packing). Radii are `BOKEH_RADIUS_RANGE` (14-150), skewed small. The count (`BASE_DISC_COUNT`, 40 per 1200x800) scales with canvas area. It was 70, which looked busy.
  - Tried and removed: rounded hexagons (camera aperture) with a dark inner hexagon, larger and fainter. The aperture look was too strong.
  - Gradients are defined in `<defs>` outside the depth layers. With parallax each layer is its own `<svg>`, and `url(#id)` still finds them in the shared document.
  - Colours are emitted as hexes only; `opacity` and `stop-opacity` are plain numbers, so tones still work.
  - Tests: [bokeh.test.ts](../src/lib/components/PaletteBackground/bokeh.test.ts).
  - Tried and removed: `glowBands`, the `bands` fan with blurred gradient fills and gradient edge strokes. It did not look good.

- `mondrian`: a light ground cut into blocks by thick black lines, with some blocks in palette colours. [mondrian.ts](../src/lib/components/PaletteBackground/mondrian.ts) `mondrianArt()` and `layoutBlocks()`.
  - `layoutBlocks()` splits the canvas in two, again and again (a binary space partition). Each cut is on the longer side most of the time (75%), so blocks don't get long and thin, and sits on a multiple of `GRID` (40), so lines in different blocks line up. Both halves keep at least `MIN_BLOCK` (80) on each side, so there are no slivers. A block too tight for any grid line is cut down its middle.
  - After `MIN_DEPTH` (3) cuts each block has a rising chance to stop (`BASE_STOP_CHANCE` 5% plus `STOP_PER_LEVEL` 6% per level), which still leaves a few bigger blocks among small ones. These numbers were 110, 2, 12% and 10%, which looked too sparse; lower the stop chance or `MIN_BLOCK` for more, raise them for less.
  - A split line runs the full width of its block only, not the whole canvas. This is not how Mondrian painted (his lines usually cross the whole canvas), but it avoids tiny cells and is far simpler to keep balanced.
  - Colours: only the palette's own colours, plus black (`LINE_COLOUR`) for the lines. Nothing is mixed or tinted, so the palette keeps its character. The ground is the lightest palette colour. 35% of blocks (`COLOURED_SHARE`, at least one) are filled, from a shuffled deck of the other colours that are not too close to the ground (`colourDistance` over 0.18), so they repeat as little as possible. If none stand out, any other colour is used; a one-colour palette uses that colour. Adjacent blocks can still share a colour. Black is a plain hex, so tones still recolour it.
  - Lines are rectangles, extended half a line at each end so they overlap cleanly at junctions. Their width is `lineWidthFor(gap)`: `BASE_LINE_WIDTH` (10) plus `gap` (0 to 0.4) times 35, so 10 to 24. `gap` is the Border slider; it only changes the width, not the layout, so dragging it is smooth. The wallpaper maker shows the slider for `mondrian` as well as `hexagons`.
  - Like the other non-layered variants it slides as one piece with parallax.
  - Tests: [mondrian.test.ts](../src/lib/components/PaletteBackground/mondrian.test.ts) check the blocks tile the canvas exactly, the minimum size, grid alignment, determinism and hex-only colours.

- `stripes`: parallel stripes of different thickness, side by side across the canvas. [stripes.ts](../src/lib/components/PaletteBackground/stripes.ts) `stripesArt()` and `layoutStripes()`.
  - Every stripe shares one angle (one of `STRIPE_ANGLES`, 0, 45, 90 or 135 degrees: horizontal, vertical, or 45 degrees either way, picked by `rotationFor()` as the seed modulo 4, so seeds 1, 2, 3, 4 give 45, 90, 135, 0. The seed reaches the generator as `GeneratorInput.seed`, as well as the `random` made from it. It takes nothing from the random stream), so the layout is one-dimensional. Measure across the stripes: the canvas is a range `span` wide (`height * |cos| + width * |sin|`, which also holds at steep angles), and the stripes are consecutive pieces of it, each starting where the last ended. They tile it exactly, so nothing is stacked or covered up. This replaced stripes at many angles stacked on a backdrop, which looked scattered, and then near-horizontal stacked ones.
  - All stripes sit in one `<g transform="rotate(...)">` about the canvas centre. Each is a `hypot(width, height)` long `<rect>`, enough to reach past both sides at any angle.
  - Thickness is spread evenly on a log scale between `STRIPE_THICKNESS` (14 and 140), so there are many thin stripes and a few thick ones, in random order. The last stripe runs off the end of the canvas rather than being cut, so every stripe keeps its full thickness.
  - There is no count setting: stripes are added until the span is filled, so a taller canvas gets more stripes of the same size.
  - Colours come from the whole palette, in order of similarity. `orderBySimilarity()` in [paletteUtils.ts](../src/lib/components/PaletteBackground/paletteUtils.ts) finds the shortest path through the colours by `colourDistance()` (exact up to `MAX_EXACT_ORDER`, 8, by trying every order; nearest-unused-colour beyond that), oriented dark to light. Stripes step along that path one colour at a time and turn round at each end (`stepAlong()`: 0 1 2 3 2 1 0 1 ...), so a stripe is always next to the colours most like it, the sequence never jumps from one end of the palette to the other, and a stripe is never the same colour as its neighbour. Only a one-colour palette has to repeat. The start position and first direction come from the random stream. Prominence no longer affects how often a colour appears (every colour gets an equal share), as it was weighted before. A same-colour hairline stroke (`SEAM_STROKE`) hides anti-aliasing seams, and a backdrop in the first colour sits behind in case rounding leaves a gap at an edge. There is no border or gap setting.
  - Parallax: no depth layers, so the whole canvas slides as one piece like the other flat variants. Depth layers were tried, by random depth and then by thickness, and looked bad. The cause is that stripes tile the canvas with no overlap, so sliding some by different amounts opens gaps between neighbours, and the only fix (a copy that stays put underneath) leaves an echo of each moving stripe.
  - Tests: [stripes.test.ts](../src/lib/components/PaletteBackground/stripes.test.ts) check the angle is one of `STRIPE_ANGLES` by the seed modulo 4 and the span at every angle, that all stripes share one rotated group and move as one piece with parallax, that stripes meet end to end across the whole span, the thickness range, that stripe colours step to a neighbour in the similarity order (also `stepAlong()` and `orderBySimilarity()` directly), that the stripes reach across the canvas, and palette-only colours.

- Tried and removed: `emoji`, the `checkerboard` with a greyed, blended emoji (from one themed group) on some squares. It did not work out. Emoji are text drawn by the viewer's own font, so they differ from system to system, and getting the density, size and blend right did not come together.

- `midcentury`: a grid of 1 x 2 cells (one wide, two tall). Every cell holds the same shape (a half-disc arc or a triangle) facing the same way (left or right), both chosen once per seed. Options `shape` (`CELL_SHAPES`) and `facing` (`CELL_FACINGS`) fix them. The controls show every option as a row of preview tiles, like the variant picker (see `WallpaperControls`). Each cell has two palette colours (a ground and a different ink). [midcentury.ts](../src/lib/components/PaletteBackground/midcentury.ts) `midcenturyArt()`, `layoutCells()` and `shapeMarkup()`.
  - The board picks a cell width from `CELL_WIDTHS` (80, 100, 120). The grid is centred and runs past the canvas, like `checkerboard`.
  - The arc's diameter is the cell's whole tall edge; the triangle's base is that edge and its tip is the middle of the opposite edge.
  - Colours follow a pattern, not chance. The palette (in a seed-shuffled order) repeats in diagonals: a cell's ground is colour `column + row`, and its ink is `inkGapFor()` places further along. A ground is then never the ink of its left or upper neighbour, and an ink never their ground, so a join between a ground and a shape is never one solid colour (this is to hide Firefox seams). Palettes of three or fewer colours cannot avoid every clash.
  - The grid is placed by one `translate` on a single group, with every cell at its position in the grid, rather than a `translate` per shape.
  - A one-colour palette inks in black. No gap setting. Slides as one piece with parallax.
  - Tests: [midcentury.test.ts](../src/lib/components/PaletteBackground/midcentury.test.ts).

- `artdeco`: art deco fans in rows, each row shifted by a radius from the one above. [artdeco.ts](../src/lib/components/PaletteBackground/artdeco.ts) `artDecoArt()`, `archMarkup()`, `clamshellMarkup()` and `fanColours()`. Option `style` fixes the sub-type (`peacock`, `sunburst` or `clamshell`).
  - Each fan is a whole circle. Rows are `ROW_STEP_SHARE` (0.6 of a radius) apart, fans in a row `COLUMN_PITCH_SHARE` (2.9 radii) apart, and odd rows shift by half of that. Rows are drawn top to bottom, so each covers part of the one above. Each fan has a solid fill, which hides the ones behind it. The spacing is looser than fish scales (0.5 and 2), so a sliver of background shows between fans.
  - `peacock` and `sunburst` are arches, not circles: a half circle of the radius on a rectangle as wide as the circle (`archPath()`), with walls `ARCH_WALL_RADII` high: two radii for the peacock (a half circle on a square, 1 wide to 1.5 high) and one for the sunburst (1 to 1). They radiate from the middle of the bottom edge. Rows are `ARCH_ROW_STEP_SHARE` (13/30) of the arch's height apart and fans in a row `ARCH_PITCH_SHARE` (2.5) radii apart.
  - Styles in `FAN_STYLES`, one per seed: `peacock` (nested arches, alternately ink and background, with the same walls and half circle centre so every band is the same width all the way round; shrinking one arch evenly stretched the bands), `sunburst` (`SUNBURST_RAY_COUNT`, 39, cubic bezier rays from the bottom centre to points evenly spaced round the arch's outline by `archOutlinePoint()`. Each leaves straight up and bends out towards its end (`rayCurve()`). Nothing else inside the arch), `clamshell` (`FEATHER_COUNT` feathers radiating from the apex, each narrow at the base and wider at the tip, which is a rounded arc (`TIP_ARC_SHARE` of the feather's width). There are no other lines (an arc across each feather was tried and removed). Each feather has its own solid fill, from the colour at its height, so it hides what is behind it. A plain disc behind them fills the notches between the rounded tops. No ribs or clip). The radius comes from `FAN_RADII` (56, 72, 90).
  - Monochrome: every line is the palette's third darkest colour (the lightest, for a palette of one or two). The fills step from the darkest colour at the top to the second darkest at the bottom, one colour per row (`groundAt()`), which reads as a gradient. Palettes of one or two colours are darkened with black to make up the two fill colours.
  - A real gradient (the same two colours, top to bottom) sits behind the fans and shows in the gaps. It only has to be close to the fills. When fans were packed tight, the gradient had to match each fan's fill exactly to hide it and showed seams where it did not. Slides as one piece with parallax. No gap setting.
  - Tests: [artdeco.test.ts](../src/lib/components/PaletteBackground/artdeco.test.ts).

- `80s`: a random pastiche of squares, triangles, crosses (`x`), lines and squiggles. [eighties.ts](../src/lib/components/PaletteBackground/eighties.ts) `eightiesArt()`, `layoutShapes()` and `shapeGeometry()`.
  - The background is the palette's darkest colour (`splitColours()`); each shape takes a random one of the rest. A one-colour palette draws in white.
  - Shapes are placed by packing circles with `packCircles()` (see [packing.ts](../src/lib/components/PaletteBackground/packing.ts)), largest first, with `PACKING` settings (radius 16 to about 96, 30000 tries so small circles fill the gaps between the big ones, 16 units between circles). Each circle then gets a random turn and colour, and a kind weighted by its size (`kindWeights()`): big circles mostly get squares and triangles, small ones mostly lines and crosses, so lines and crosses stay small and solid shapes large. Every shape is drawn inside its own circle (`shapeGeometry()` fits it to `radius`), and circles never touch, so shapes cannot collide however they turn. Shapes are drawn at `SHAPE_SCALE` (0.88) of the circle, so the points of triangles and the ends of crosses and lines leave clear space. The 16 unit gap covers the stroke, which spills a little past the shape, and a doubled line: `reachOf()` is the worst-case reach of any paint, and it is tested that two shapes' reaches never meet. Earlier this was a jittered grid with random sizes, which let shapes overlap and left gaps.
  - Squares and triangles are filled (`FILLED_SHARE`, 0.5) or outlined. Crosses, lines and squiggles are always strokes (`STROKE_WIDTH` 6, round ends). A squiggle is a quadratic curve followed by `T` curves, which mirror the one before. It is gentle on purpose: `SQUIGGLE_WAVES` (3) half-waves, each `SQUIGGLE_HEIGHT` (0.16) of the radius tall, so neighbouring squiggles do not overlap.
  - Rarely (`DOUBLE_SHARE`, 0.1) a line or squiggle (`DOUBLEABLE`, and only those) is drawn twice, as two copies 2.2 stroke widths apart, either side of the centre. Triangles, squares and crosses were doubled at first, and looked like a mistake.
  - Shapes have no `transform`. `shapeGeometry()` takes a `place` function that maps each point, and `shapeMarkup()` uses it to turn and move the points to their final canvas coordinates, so each shape is one `<path>` or `<polygon>` (two for a double). A `<g transform>` for every shape made the renderer apply hundreds of transforms, and made each parallax layer more work to composite. Now each layer is a flat list of shapes in one SVG, moved as one piece by the host.
  - Parallax: depth layers, like `circles`. A shape's size for depth is its circle's radius (bigger is nearer), over the range `PACKING` produces, through `depthLayers()`. The background stays put. `80s` is in `DEPTH_VARIANTS` in [generators.ts](../src/lib/components/PaletteBackground/generators.ts).
  - Tests: [eighties.test.ts](../src/lib/components/PaletteBackground/eighties.test.ts).

- `emoji-storm`: circles packed like `80s`, but smaller and denser (`PACKING`: radius 10 to 70, gap 3), with an emoji in every one and no other shapes or lines. [emojiStorm.ts](../src/lib/components/PaletteBackground/emojiStorm.ts) `emojiStormArt()`.
  - Background: a gradient from the darkest colour towards the second darkest (`GRADIENT_REACH`, 0.35 of the way), top to bottom.
  - Blur: depth comes from size (`depthsOf()`), split into `DEPTH_LAYERS` steps. The nearest step is sharp and the furthest has a blur of `MAX_BLUR` (`blurForLayer()`). The blur is the last step of the filter, so there is one filter per colour per step.
  - Option `emoji` fixes the emoji; otherwise the seed picks one from `RANDOM_EMOJI` (Smileys & Emotion, Food & Drink, Animals & Nature and Objects, typed in by hand, so newer emoji may be missing). One emoji per picture. The API and URL accept any single emoji (`isEmoji()`; flags, skin tones and joined emoji too), and text-default ones get the colour selector. The controls list only `STORM_EMOJI`, a short 80s set; `VariantOption.accepts` lets the option take more than it lists, and `glyphs: true` shows each emoji instead of a preview.
  - Each emoji is a `<text>` with a `tintFilter()`: greyscale, soft-light blended onto the colour (mid grey is the colour, darker greys shade it and lighter ones lift it, with no clipping; `multiply` left dark parts like a brown poop dark, and `screen` blew the lights out to white), masked by the emoji's own alpha, then blurred. The filters are in a `<defs>` that stays put with parallax. Tone changes the `flood-color` like any other hex.
  - Emoji lean up to `MAX_TILT` (25 degrees) either way, so they stay upright enough to read.
  - Emoji come from the viewer's fonts, so they look different per platform, and the exported PNG uses the exporting browser's.
  - Tests: [emojiStorm.test.ts](../src/lib/components/PaletteBackground/emojiStorm.test.ts).

- `neon`: glowing rings growing outwards from the middle of the canvas, over a dark gradient. Option `shape` (`NEON_SHAPES`: circle, triangle, square, pentagon, hexagon, which is everything the seed can pick from `RING_SIDES` and the two line styles) fixes the ring's shape (`shapeFor()`). The rest stays with the seed. [neon.ts](../src/lib/components/PaletteBackground/neon.ts) `neonArt()`, `layoutNeon()`, `ringPoints()`, `ringPath()`, `dashesFor()` and `glowColour()`.
  - Colours: the darkest colours make the background gradient and the rest colour the rings, using `splitBokehColours()` from [bokeh.ts](../src/lib/components/PaletteBackground/bokeh.ts) (the same split). Rings step through the lights, one colour each.
  - Rings are all round the middle of the canvas (always its centre), from a small one (`INNER_RADIUS_SHARE`, 0.12 of the shorter side) out past the corners. They are circles (`curve`) or nested polygons of 3 to 6 sides (`sharp`), all turned the same way. A polygon's sides, not its corners, are `radius` away, so rings are the same distance apart wherever they face each other. Nothing leaves the rings. An earlier version had tails running out of a loop, and a version before that scattered many loops; neither worked.
  - Bands: rings come in bands (`RINGS_PER_BAND`, 2 to 5, spaced `RING_SPACING`, 17 to 26) with an empty gap between bands (`BAND_GAP`, 34 to 90). Bands are added until the outer ring is past the corners.
  - Gaps and shifting patterns: each band has a pattern from `BAND_PATTERNS`, picked by `dashesFor()` and shared by its rings: `solid`, `dashed`, `dotted` (a dash of 0.1, so the round line caps are dots) or `arcs` (long pieces with gaps, hinting at a ring). Each ring's `stroke-dashoffset` is slid along from the one inside it by `PATTERN_SHIFT` (8 to 40 units, either way for the whole band), so the gaps wander round the band instead of lining up.
  - Staggered rotation: one of `ROTATION_MODES` per picture. `aligned` keeps every ring facing the same way. `alternate` turns every other band half a side, so corners face sides. `progressive` turns each band `BAND_TWIST` (8 to 24 degrees, one way) more than the one inside it, so bands spiral. The last two also twist each ring in a band `RING_TWIST` (1 to 6 degrees) more than the one inside it, so a band fans out. A circle looks the same turned, but its path starts at a new angle, so its dashes start in a new place and the turn staggers a circle's pattern too. Turned polygons cross each other where their corners poke past the next ring's sides; that is wanted, as the glowing lines interlace. Nested polygons that are not aligned cannot avoid crossing at large radii.
  - Line thickness: one of `THICKNESS_MODES` per picture, as a multiplier (`THICKNESS_RANGE`, 0.5 to 2.2) on every layer's width, stored as `Ring.thickness`. `even` is 1 everywhere. `banded` gives each band its own. `tapered` goes steadily thin to thick, or thick to thin, across the rings of a band. `swelling` grows (or shrinks) with distance from the middle, like perspective. The thickest line, 2.2 times the main width (about 10), stays under the closest ring spacing (17), so neighbours do not merge. The glows scale by the same multiplier, so a thick line has a thick halo.
  - Layers, bottom to top (`LAYERS`, `MAIN_WIDTH`): a wide (16) glow with blur 14, a narrower (9) glow with blur 5, and the true colour (4.5), not blurred. The two glows have more chroma and a hue turned a little (`glowColour()` in OKLCH; the turn is up to `MAX_HUE_SHIFT`, 16 degrees, and the two glows turn by different shares of it). Nearly grey colours stay grey, so a white line does not get a tint it never had. Each layer is one `<g>` with one filter, not a filter per ring, so only two blurs are done, however many rings there are. All three layers use the same dashes and offsets, so the glows line up with the rings.
  - Moves as one piece with parallax (no depth layers). The filters are in the same `<defs>` as the art, which is wrapped whole into the layer.
  - Tests: [neon.test.ts](../src/lib/components/PaletteBackground/neon.test.ts).

## Tones

The `tone` prop (`PaletteTone`: `original`, `pastel`, `dark`, `subtleDark`) recolours the art. `original` is untouched. Code is in [tones.ts](../src/lib/components/PaletteBackground/tones.ts) and [oklch.ts](../src/lib/components/PaletteBackground/oklch.ts).

- `generatePaletteArt()` builds the art from the original palette, then `applyTone()` replaces every `#rrggbb` in the markup.
  - The layout is identical in every tone. Generators choose pairs, roles and layouts with contrast thresholds (`MIN_PAIR_CONTRAST`, `buildColourPairs()`, `assignColourRoles()`), so a softened palette would make them choose differently.
  - Colours the generators derive by mixing with `#ffffff` or `#000000` go through the same map, so black and white land on the tone's `floor` and `ceiling` and nothing needs changing in the generators.
  - Generators must only emit 6-digit hex colours (no `rgb()`, names or opacity), or those colours skip the map. A test checks the layout stays the same.
- `buildToneMap(palette, tone)` returns a cached `(hex) => hex`. It works in OKLCH and changes lightness and chroma only. Hue is held, because OKLCH hue stays steady as lightness changes (HSL drifts).
  - Lightness: the palette's own lightnesses are squeezed to fit the tone's `band` and moved only as far as needed to sit inside it, in the same order and proportions. It only squeezes, never stretches, so a narrow palette stays narrow, and a palette already inside the band keeps its lightness. It is not an inversion: that would make a cream ground black and break the colour roles.
  - `MIN_LIGHTNESS_STEP` keeps palette colours apart so pastel cannot merge two into one hex.
  - Lift: `lift` (below 1) reshapes lightness between the squeezed ends so darker colours rise more than lighter ones. A pastel keeps its darkest colour as a soft accent (about L 0.72) instead of every colour piling up near white.
  - Saturation, not chroma: each colour's saturation (`saturationOf()`: chroma as a share of `maxChroma()`, the most sRGB allows at that lightness and hue) is pulled `saturationBlend` of the way to `saturationTarget`. Scaling absolute chroma made pastels look like lightened colours, because the gamut is narrow near white and the chroma vanished. Blending (not setting) keeps vivid and muted colours distinct. Near-neutrals (saturation under `NEUTRAL_SATURATION`) are pulled less, so whites and greys stay neutral.
  - A colour outside sRGB loses chroma at the same hue instead of clipping (`oklchToHex()`).
  - `brightnessCompensation` lowers lightness by chroma, because saturated colours look brighter than their lightness says (Helmholtz-Kohlrausch).
  - `neutralChroma` stops greys, blacks and whites going dead; colours with almost no chroma take the palette's most vivid hue.
- Tones: `pastel` is light with a lifted, narrow-ish band and moderate saturation. `dark` keeps the original contrast on dark surfaces and mostly keeps saturation. `subtleDark` is pastel's low contrast and moderate saturation on a dark band.
- The numbers in `TONE_SETTINGS` are starting values. Tune them with the `Tones: ...` stories, which show every palette in every tone.
- Apparent hue can still drift with lightness (Bezold-Brücke, Abney), mostly in reds and oranges. If the stories show it, add a per-hue nudge in `buildToneMap()`.
- Tests: [tones.test.ts](../src/lib/components/PaletteBackground/tones.test.ts).

## Parallax

`circles`, `flowers` and `bokeh` split into depth layers. Every other variant has no sizes to put in depth, so `generatePaletteArt()` wraps the whole artwork, background included, in one `depth-layer` with `--shift` `WHOLE_CANVAS_SHIFT` (0.5, `wholeCanvasLayer()`), and it slides as one piece. The bleed keeps its edges covered. Size stands in for distance: larger shapes are nearer. The generator builds `DepthItem`s (`markup` and `size`) and calls `depthLayers()` ([depthLayers.ts](../src/lib/components/PaletteBackground/depthLayers.ts)) with the `depth` settings (`DepthSettings`) from `GeneratorInput`. While `parallaxPoint` is `undefined` the markup is unchanged.

- Props: `parallax`, `parallaxPoint` (0 to 1), `parallaxDistance` (0 to 80). The Storybook `Playground` has controls for all of them.
- Depth of field (blurring by distance) was tried and removed: SVG blur filters were slow, especially while layers moved, and did not look good.
- [depth.ts](../src/lib/components/PaletteBackground/depth.ts) has the depth maths, with no SVG in it, so it can be reused.
  - `depthsOf()` gives each item a depth, 0 (furthest) to 1 (nearest): its size on a log scale (`depthOf()`).
  - Each depth is then moved by up to `DEPTH_JITTER` (0.12), so equal sizes are not all equally far. The nudge is seeded from the item's markup, so it is repeatable and does not use the generator's random stream (turning parallax on does not rearrange the art).
- `depthLayers()` splits items into `DEPTH_LAYERS` (6) equal steps of depth, not equal counts. There are many small shapes and few big ones, so the big ones land in the near layers alone and get the most movement. (Equal counts per layer was tried and put the few big shapes in with mid-sized ones, so they barely moved.) Layers are drawn far to near, so near shapes are on top. Each layer is wrapped in comments carrying its shift, `<!--layer:n-->...<!--/layer-->`; `splitLayers()` pulls them back out (see below).
- [parallax.ts](../src/lib/components/PaletteBackground/parallax.ts): `parallaxShift()` gives a layer's `--shift` from its depth and `parallaxPoint`. The layer at the point stays still. Nearer layers go one way, up to 1 (the full `parallaxDistance`) for the nearest; further layers go the other way but only up to `FAR_SHIFT_SHARE` (0.3), so the many small shapes move little and the big ones move most.
- Each layer is its own `<svg>`, so the browser slides it on the GPU. Moving `<g>`s inside one SVG was slow: SVG children are not composited, so every cursor move repainted the whole artwork.
  - `PaletteBackground` calls `splitLayers()` on the artwork: `base` (the backdrop, which stays put) and the layers. It draws `base`, then each layer, as separate `.palette-background-layer` SVGs, stacked in `.palette-background-stack`.
  - The cursor is tracked on `window` (`pointerPosition()`, -1 to 1 across the component, clamped), at most once per frame. `parallaxOffset()` gives the slide against the cursor in canvas units; it is converted to screen pixels (`pixelsPerUnit`) and set as `--parallax-x` and `--parallax-y` on the stack only, so the content in `children` is not restyled.
  - The last pointer position is kept at module level (`lastPointer`), so a background created later (e.g. a keyed swap in the wallpaper maker) starts at the real cursor position, not the centre. The first placement is instant: easing (the `.following` class) switches on two frames later, so layers never slide in from the centre on load or swap.
  - A layer translates by those times its `--shift` (`translate3d`, `will-change: transform`, short transition).
  - Each SVG is sized in pixels to the art (container plus bleed) and centred, because an SVG clips what is outside its own box.
- While `parallax` is on, the art is drawn `PARALLAX_BLEED` (80) larger on every side and the `viewBox` crops back, so sliding layers never show bare edges. This changes the layout once, when `parallax` is switched on; `parallaxDistance` changes do not redraw.
- Reduced motion: layers do not slide when `html[data-reduced-motion='true']` (set by the host app, e.g. aknotes' `devdocs/reduced-motion.md`).
- Background circles in `flowers` are not layered. Flower dots are smaller than any flower, so they are the furthest.
- Tests: [depthLayers.test.ts](../src/lib/components/PaletteBackground/depthLayers.test.ts).
